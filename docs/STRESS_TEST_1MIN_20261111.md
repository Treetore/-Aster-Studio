## 四、判定：散热不是直接原因

**支持"不是散热"的证据**
1. **25 分钟连续受载、88.6°C 平均、峰值 95.3°C，一次都没崩**；若过热是触发条件，这个时长/温度足以复现。
2. 负载段温度四段稳定（88.3–88.9°C），说明散热已进入热平衡，不存在"越跑越热"的累积效应；而两次真实崩溃都发生在**开跑后 2–5 分钟内**，时间特征与热 soak 不符。
3. 热限流仅 8 个采样点触发（GPU 确实降频到 1095 MHz），但只是**降性能**，没有产生 141/CUDA 错误、也没有冻机。
4. 两次崩溃的堆栈都落在**同一段软件路径**（`cast_maybe_lowvram_patch` → 显存换入拷贝），且伴随 RAM/commit 贴顶（本次成功运行 RAM 也低到 1.28GB、commit 46.7GB，说明内存始终紧张）。

**散热的作用（真实但非主因）**
- GPU 长期运行在 **87–95°C**，高于 87°C 设计目标 → 功耗被压在 68W 左右（140W 上限用不到）、频率掉到 1.1–1.7GHz，**热是"余量消耗者/风险放大器"**；
- 显存结温读不到（N/A），仍属监控盲区。

**结论**：本次压力测试否定了"散热单独导致崩溃"。更可能的触发是**软件路径（动态显存 + LowVRAMAttention 权重换入）在 15s/362 帧负载下的边界问题，叠加主机内存贴顶**；散热与内存压力降低了容错余量。

### 5.3 第二轮结论

1. **两个崩溃配置均未能复现崩溃**：crash#1 第一遍 15/15 通过；crash#2 四段全部完成。热条件与崩溃当时相同（负载段 88.7°C、峰值 94.7°C、热限流个位数），因此**散热不是触发因素**的结论被加强。
2. 崩溃更依赖**环境状态组合**：原崩溃时是 **dGPU 驱屏 + 内存高度紧张（commit 43–47GB）**；现在是 **iGPU 驱屏 + 跑前 free（起跑 RAM 23GB）**。
3. 15s + two_pass 在 8GB 上**性能不可行**（第二阶段约 20 分钟/步），应从 15s 配置中移除。
4. 温度仍偏高（88.7°C 平均、峰值 94.7°C），建议清灰/硅脂/风扇策略，属于寿命与性能问题，不改变稳定性结论。
