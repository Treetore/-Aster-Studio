# MiniMax H3 720p 15s 优化实录（2026-11-15）

目标：在 **RTX 4070 Laptop 8GB / 32GB RAM** 上稳定产出 **1280×736（720p 级）15 秒** H3 视频。
结论：**3×5s 分段 + 首帧接力 + ffmpeg 拼接** 是当前最稳路线；单次上下文窗口可做但耗时约 2 倍。

## 1. 硬件与基线

| 项 | 值 |
|---|---|
| GPU | RTX 4070 Laptop 8GB（TGP 115W，iGPU 驱动显示） |
| RAM | 32GB（H3 运行时常驻 ~30GB，余量 <2GB） |
| ComfyUI | v0.45.3，torch 2.13+cu130，SageAttention 2.2 |
| 模型 | `minimax_h3_fl2va_pruned_int8_convrot`（19.5GB）+ `qwen3vl_32b_minimax_h3_nvfp4_awq`（14.6GB TE） |
| 默认优化 | `optimize=sage`（MemoryEfficientSageAttentionPatch），`--fast fp16_accumulation --cuda-malloc --vram-headroom 1.0` |

## 2. 实测数据

| 配置 | 结果 |
|---|---|
| 5s / 720p / 8 步 / optimize=max / **VAEDecodeTiled** | 总 **15:30**（采样 10:08，解码约 5:00）；VRAM 峰值 6.3GB，温度 89.3°C |
| 5s / 720p / 2 步 / **sage** / 普通 VAEDecode | 总 302s；稳态 **44s/步**（max 为 74–80s/步，Sage 提速约 1.7×）；解码 166s |
| 15s / 720p / 4 步 / turbo4 / **ContextWindows 124/39** | 单窗口 ≈2 分钟、4 窗口/步 → 采样约 30 分钟；已中止，确认窗口机制可用但偏慢 |
| 5s / 720p / 4 步 / turbo4 / sage（分段第 1 段） | **13:58**（含 5:10 模型初始化 + 2 分钟采样 + 约 6 分钟解码），输出 1280×736/24fps/含 AAC 立体声 |
| 3×5s 拼接 15.5s | 见 `logs/h3_720p15s_film1_report.json` |

要点：
- **Sage 是最大单项加速**（每步 74→44s）；`optimize=max` 的分块 Attention/FF 更省显存但更慢。
- **turbo 4-step LoRA** 把步数从 8 降到 4，质量可接受（细节略软，适合 720p 动态镜头）。
- **VAE 解码是第二大成本**：720p×124 帧普通解码约 3–6 分钟，分块解码更慢（约 5 分钟）。
- **上下文窗口**（`MiniMaxH3ContextWindows`）能一次生成 362 帧，但每步要串行跑 4 个窗口，总耗时约为分段的 2 倍。
- RAM 压力会让首次模型初始化从 ~90s 拉长到 ~5 分钟（30/32GB 占用，pinned host memory 吃满）。

## 3. 方案对比

| 方案 | 采样 | 解码 | 总耗时 | 连续性 | 结论 |
|---|---|---|---|---|---|
| 单次 720p 15s + ContextWindows | 4 窗口 × 4 步 ≈30min | ~8min | ~40min | 最好（窗口融合） | 可用但慢 |
| **3×5s 分段 + 首帧接力** | 3 × 4 步 ≈6min | 3 × 3–6min | **~20–30min** | 首帧接力，衔接可接受 | **推荐** |
| 608×352 生成 + latent 放大 | 快 | 放大+精修另计 | 20min+ | 精修耗时高 | 备选 |

## 4. 使用

```powershell
# 分段成片（默认 3 段 = 15.5s）
python tools/h3_720p15s.py --segments 3 --tag film1 --steps 4

# 单段验证（5s，检查画质/耗时）
python tools/h3_720p15s.py --segments 1 --tag seg1
```

- 输出：`ComfyUI/output/video/MiniMax_H3_720p15s_<tag>.mp4`
- 分段文件与首帧：`logs/h3_720p15s_<tag>/segNN.mp4`、`ComfyUI/input/h3_<tag>_segNN_last.png`
- 报告：`logs/h3_720p15s_<tag>_report.json`

服务端也提供模板 **`minimax_h3_t2v_720p15s`**（单次上下文窗口版）：
`workflow.resolve("minimax_h3_t2v_720p15s", {"prompt": ...})` → 1280×736 / 362 帧 / 4 步 / turbo4 / context 124-39。
启动器「小工具」页新增「H3 720p 15s 成片」按钮（调用分段工具）。

## 5. 画质与调参

- 4 步 turbo：动态镜头可用，静物细节偏软；追求画质改 `--steps 6`（+1.5 分钟/段）或 8 步 + 8step LoRA（+3 分钟/段）。
- 分割处若出现跳变：把 `--frames` 改为 141（17×8+5）或把上一段最后一帧作为下一段首帧（工具已自动做）。
- 显存吃紧时：`optimize=max` + `--tiled`（更慢）；或把分辨率降到 1152×672 再 ffmpeg 放大。
- 温度：720p 持续采样 85–90°C，属正常；功耗 110–115W。

## 6. 已知限制

1. 15s 单片仍在 20–30 分钟量级；根因是 20GB 模型 + 15GB TE 的权重流式加载与 720p 解码成本。
2. 分段拼接处音频可能不连续（H3 每段独立生成音频），必要时用外部配乐替代。
3. 360 帧单次上下文窗口能跑通但更慢，适合对连续性要求极高的镜头。


## 7. 解除 H3 显存限制（2026-11-15）

为让 H3 在 8GB 上不再被资源守卫拦下：

1. `settings.safety.unlimited_h3 = true`：H3 视频模板跳过 preflight 的 VRAM/RAM 阈值（风险等级仍会显示，但不阻断）；
   仍保留：ComfyUI 存活检查、队列/单飞、watch 里 <1GB RAM 的崩溃保护。
2. ComfyUI 启动参数 `--vram-headroom 1.0` → **0**：不再预留 1GB 显存给系统。
3. 启动器「设置 → 资源守卫」提供开关，可随时恢复默认阈值（min_ram 3GB / trip 1GB / VRAM 300MB）。
4. 仅对 H3 视频生效；Qwen 图像模板仍按原守卫（4096² 等超限会拒绝）。


## 8. 模型切换释放策略（2026-11-15）

本地策略文件：`data/model_policy.json`

```json
{"release_on_model_switch": true}
```

规则：
- 每次生成成功后记录模型族到 `data/model_policy_state.json`；
- 下一条指令若模型族不同，先 `POST /free {unload_models:true, free_memory:true}` 并等待显存释放（最多 20s），再提交新任务；
- 同族不释放：
  - `moss_image` ↔ `moss_image_edit` → moss
  - `qwen_image` ↔ `qwen_image_edit` → qwen_image
  - H3 `t2v/fl2v/720p15s/h3_image` → h3_fl2va；`r2v` → h3_ref2va（不同 checkpoint，切换会释放）
- 只调用 `/free`，不重启 ComfyUI/Web、不动 cloudflared 隧道；日志 `logs/model_policy.log`。

实测（512×512/8 步）：
- moss → moss：不释放（5.1s）
- moss → qwen：释放（等待 1s，日志记录 moss -> qwen_image），新任务 53.6s 完成
